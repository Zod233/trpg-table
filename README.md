# 跑团工坊 · TRPG Table

**把一个剧本文件夹交给豆包，你就有了一个不会忘主线的 KP。**

不用订阅、不用买 API key、不用写一行代码。单人版已经在真本上完整跑通过一次团——从车卡到结团，四个晚上，没有卡死在中途。

**第一次用，别读这份 README，直接看 [`docs/快速上手.md`](docs/快速上手.md)**：从装环境、生成会话、打包，到在豆包里说出第一句话，一步一图，照着抄就能开局。

---

## 这个仓库解决的是什么

现在「让 AI 当 KP」的常见做法，是把模组贴在聊天框里，聊三轮它就开始漏：忘了谁欠你一碗面、忘了地窖门是从里面闩的、忘了你上一场已经问过那个护士。跑得越久，漏得越多，最后变成一个会编故事的聊天机器人，而不是一个 KP。

所以这里要解决的不是「AI 会不会扮演 KP」，而是**「AI 能不能不漏事」**。

一次团被拆成四层，每层都能单独检查：

| 层 | 装什么 | 为什么单独存在 |
| --- | --- | --- |
| `scenarios/` | 剧本母本，六件骨架 | 剧本只描述世界，不写规则数值 |
| `systems/` | 规则包（COC 7 版、D&D 5 版） | 判定、车卡、成长、战斗，一套规则一个包 |
| `keeper/` | KP 的纪律与人设 | 明暗投、抗嘴炮、注意力分层、判例复核 |
| `sessions/` | 一次团的全部记录 | 一次团一个文件夹，装载清单之外不读 |

换剧本不改代码，换规则不改剧本，团与团之间不串数据。

## 它管得住什么，管不住什么

**管得住**：数值不漂、主线不断、承诺不忘、判例可查、骰值可复算。

**管不住**：当场的即兴、读空气、把一个烂梗变成好戏。这些还是得靠人——或者靠一个真的很好的模型。

它是一副**能约束 AI 不出错的骨架**，不是一个能替你带好团的产品。这个定位不打算改。

## 五分钟开一团

```bash
# 1. 用示例剧本生成一次团（也可以换成你自己接进来的本）
python tools/new_session.py --scenario rain-train --system coc7 \
    --persona 老派说书人 --characters lin-yan --rating L1 --dice KP自掷

# 2. 开局前预检，有失败项不许开局
python tools/check_session.py "sessions/<生成的文件夹>"

# 3. 打成最小运行包：只把本场要用的文件拷进 dist/，
#    模型看不到仓库的其余部分
python tools/pack_session.py "sessions/<生成的文件夹>" --with-docs

# 4. 用豆包打开 dist/<session_id>/，从 START.md 开始
```

跑到一半有事？关掉就行。回来再打开同一个文件夹，`前情提要.md` + `状态跟踪.md` + 最新一份日志就够接上——**单人团本来就不该要求你一次跑完**。

掷骰要可追溯：

```bash
python tools/roll.py 1d100 --label 侦查 --bonus 1   # 输出含时间戳与种子，可复算
```

每场结束：

```bash
python tools/archive_logs.py "sessions/<会话>"       # 只移动，不删除
python tools/check_drift.py "sessions/<会话>"        # 主线两场没推进就报警
python tools/export_stats.py sessions --out stats.csv
```

## 支持什么

| 项目 | 说明 |
| --- | --- |
| 人数 | **单人（已实战验证）**；1–6 人共用单屏只是设计目标，未实测 |
| 规则 | 内置 COC 7 版、D&D 5 版；任意系统按 `systems/_template/` 接入 |
| 剧本形态 | 线性、沙盒、调查、混合；接入见 `docs/模组接入指南.md`，单人改写见 `docs/单人玩法.md` |
| 内容分级 | L0–L3，manifest 必填，随时可喊停 |
| 长团 | 逐场日志 + 前情提压缩 + 成长规则；漂移用 `check_drift.py` 机械查 |
| 续跑 | 任意时点中断，下次只装载提要、状态与最新日志 |

## 几条设计上的硬规矩

- **母本只读**：`scenarios/`、`characters/` 不改，改动只发生在会话副本里。
- **数值单一来源**：数值只存在角色卡上，`状态跟踪.md` 只记非卡面状态，从根上消灭双写漂移。
- **记忆分层**：L0 硬事实（主线、关系、承诺）→ L1 指针 → L2 每三场一块 → L3 只留最近两场原文，更早归档不删。一句话闭环的即兴事件不进长期记忆，进长期记忆要过三问，丢弃必须留痕、可复活。
- **骰源三档**：平台骰具 / `tools/roll.py`（带种子可复算）/ KP 自掷（日志标「未审计」）。玩家可以自己掷，但必须贴工具输出；**不接受口头报数**。
- **车卡有闸门**：数值审核 + 叙事审核两关，未过审不得进场；每个规则包自带必过/必退用例，改规格就跑回归。
- **判定权只归 KP**：玩家不能要求检定、不能宣布成功、不能改难度。换做法可以，施压不行。
- **单人战斗有预算**：撤退是默认选项，三回合内必须给脱身路径，单次伤害不超过 HP 上限一半（见 `docs/单人玩法.md`）。

## 接入你自己的本

外部模组不能直接用——它写给人看，不写给模型执行。要按六件骨架拆一遍：概览、背景与真相、登场人物、线索与调查点、关键场景、结局分支，再补一节「车卡约束」（身份范围、可用职业、必用技能、时代与语言、装备限制）。

完整步骤见 `docs/模组接入指南.md`。这条路已经用 COC 与 D&D 的官方免费模组实测过：能拆、能跑、能在中途撤回。

**商业模组的原文不进本仓库**。`.gitignore` 已排除 `scenarios/local/`、`sessions/local/`、`private/`——那是本机自用的位置。规则引用与分级边界见 `docs/内容与版权.md`。

## 边界，先说清楚

- 单人版验证过；**多人实桌（4–6 人、分屏私聊、现场读空气）没有验证过**，相关文件在模板里，但不进 P1 验收。
- 它默认你在本机用豆包打开一个文件夹跑。自带界面、自带 API key 的独立客户端、手机 APP 都只是路线图上的想法（`docs/项目路线.md`），没做。
- 一个人 + 一个 AI，跑一场 2–3 小时的团，这是它现在的形状。再往上加人，是另一件事。

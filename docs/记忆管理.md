# 记忆管理

## 三条不变量

跑团可以记错很多事，但这三样错一次就毁团：

1. **主线节点状态**：推进到哪、已给出哪些信息、还缺什么。
2. **角色数值与物品**：HP、SAN、MP、技能、手上有什么。
3. **关系与承诺**：谁对谁什么态度、谁答应过什么、兑现没有、什么条件下兑现。

## 单一来源（防双写漂移）

| 数据 | 唯一来源 | 其他地方 |
| --- | --- | --- |
| HP / SAN / MP / 技能 / 物品 / 成长 | `01-车卡/<角色>.md` | 只引用，不复制数值 |
| 临时状态、伤势标记、未用完资源 | `状态跟踪.md` | 卡上不改 |
| 主线进度、关系边、承诺、时间锚 | `状态跟踪.md` | — |

原则：**同一个数字只存在于一个地方**。卡上有的不写进状态跟踪，状态跟踪有的不回写卡。

## 四层

| 层 | 内容 | 存在哪 | 每场装载 | 压缩方式 |
| --- | --- | --- | --- | --- |
| L0 硬事实 | 主线节点进度、关系边、承诺、时间锚、非卡面状态 | `状态跟踪.md` + `01-车卡/` | 全量 | 不压缩，只覆盖更新 |
| L1 索引 | 支线、伏笔、未闭指针、未解之谜、观察区 | `03-日志/前情提要.md` 上半 | 全量，有上限 | 只留指向与状态 |
| L2 摘要 | 每 3 场一块：决策 / 获得 / 失去 / 未闭环 | `03-日志/前情提要.md` 下半 | 最近 2 块全量 | 旧块压成一行 |
| L3 原文 | 逐场日志 | `03-日志/日志-00N.md` | 最近 2 场 | 更早的移到 `03-日志/归档/`，**不删除** |

## 三问归档（附留痕）

每条事件问三句：

| 问题 | 是 → | 否 → |
| --- | --- | --- |
| Q1 改变了主线节点状态？ | L0 进度 + L2 摘要 | 继续 |
| Q2 改变了数值 / 物品 / 关系 / 承诺？ | 改卡或改 L0 + L2 一句 | 继续 |
| Q3 留下未闭指针（线索、承诺、敌人、伏笔）？ | L1 一行 | 进「丢弃清单」 |

**丢弃必须留痕**：当场日志末尾写一行 `▸ 丢弃：事件｜理由｜场次`。理由必须具体（「问了一句人数，无后续指向」），不接受「不重要」。

**观察区**：玩家重复提及、追问、明确要求记住的事，即使三问全否，也先放进 L1 的观察区（≤10 行）。三场之内无咬合就删，删时记「观察期满」。

**复活**：后续场次发现某条被丢弃的事件与主线咬合，从丢弃清单取出，补 L1 指针 + L2 一行，记 `复活于场次 N`。误判可逆，不需要推翻整团。

## 事实台账（含变更链）

`主体 | 关系 | 客体 | 当前值 | 来源 | 玩家已知 | 变更记录`

- 同一主体同一关系只保留一行，**改值时覆盖「当前值」，但在「变更记录」里追加一段**：`001 戒备 → 003 欠情 → 005 敌对`。这样既回答「现在什么态度」，也回答「怎么走到这一步」。
- 来源是「推测」的，不算事实，不得据此改 L0；玩家已知为「否」的边不进公开叙述。
- 台账是唯一依据，与叙述冲突时以台账为准。

## 承诺表要写条件

`谁 | 承诺 | 对谁 | 触发条件 | 期限 | 状态`

条件式承诺（「你把货搬下去，我给你钥匙」）必须写清条件，否则兑现时没有依据。状态只三种：未兑现 / 已兑现 / 已作废；作废要写原因。

## 装载预算（含六人团）

| 层 | 单人 | 六人团 | 处理 |
| --- | --- | --- | --- |
| 角色卡 | ≤ 120 行 | ≤ 120 行 / 人 | 只装参团角色 |
| 状态跟踪 | ≤ 90 行 | ≤ 150 行 | 超了先移低频边 |
| 关系边 | ≤ 30 行 | ≤ 40 行 | 低频边移到 L1 摘要 |
| 承诺 | ≤ 10 行 | ≤ 15 行 | 作废的删掉 |
| L1 | ≤ 40 行 | ≤ 50 行 | 先删已闭环 |
| L2 | 最近 2 块 ≤ 60 行 | 同 | 旧块并成一行 |
| 日志 | 最近 2 场 | 最近 2 场 | 更早移归档 |

降级顺序：低频关系边 → 已闭环支线 → 旧 L2 块 → 日志场次数。**主线进度与承诺永不降级。**

## 回取

摘要只写指针：`见 日志-002#餐车`、`线索 L3`、`NPC 赵德贵`。需要细节时按指针只读该段落，读完不常驻。归档日志也可按指针读取，只是不进装载清单。

原则：**摘要存指向，不存原文**。

## 对账（每场开局 30 秒）

1. 卡面数值是否与上场结束一致（成长是否落卡）。
2. 主线「已给出的信息」与 L1 已揭示真相是否一致，少一条先补。
3. 关系边与承诺里有没有「人死了、物丢了、期限过了」但没有关掉的条目。
4. 上一场的丢弃清单里，有没有本场剧本会用到的东西——有就复活。

冲突优先级：**卡面数值 > L0 状态 > 日志原文 > L2 摘要**。

## 对应工具

| 工具 | 管哪一层 | 频率 |
| --- | --- | --- |
| `tools/archive_logs.py` | L3 → 归档 | 每 3 场 |
| `tools/check_drift.py` | L0 / L1 漂移（主线停滞、承诺超期、观察区到期、预算超限） | 每场开局前 |
| `tools/pack_session.py` | 物理隔离（只装本场清单） | 每次开局 |
| `tools/roll.py` | 骰值可追溯（时间戳 + 种子） | 每次判定 |

脚本只能查「表里写了什么」，查不出「表里该写却没写」的东西。对账仍是人的事。

## 为什么这样分

- 最容易错的是数值与承诺，所以数值放卡、承诺放表，都不参与任何压缩。
- 最容易膨胀的是过程，所以过程只留「有指向的」进长期记忆，其余留在日志里等归档。
- 中间层只留指针，因为线索、伏笔、支线的价值在「指向」，不在「经过」。

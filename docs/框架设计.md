# 框架设计

## 目标

一个可复用的跑团框架，不是一个跑团。把外部下载的剧本放进 `scenarios/`，框架就能用同一套 KP 支撑任意剧本、任意规则系统，并且每场团互不污染。

框架负责回答三个问题：**装载什么、隔离什么、KP 有什么权限**。剧情内容一概不在框架层。

## 三层结构

| 层 | 位置 | 生命周期 | 单场跑团可否修改 |
| --- | --- | --- | --- |
| 框架层 | `keeper/`、`docs/`、`README.md` | 长期，跨所有团 | 否 |
| 规则层 | `systems/<系统id>/` | 跨团复用，按版本冻结 | 否 |
| 会话层 | `sessions/<session_id>/` | 一次团 | 是，全部改动只在这里 |

剧本库 `scenarios/` 与角色库 `characters/` 是素材母本，只读；进会话时复制一份，改动留在副本。

## 隔离机制

1. **manifest 是唯一装载入口**：`sessions/<本次>/00-本次设定.md` 的 `装载清单` 列出本场可读的文件，清单外一律不读。
2. **副本优先**：剧本、角色卡进会话即复制；母本与副本冲突时以副本为准。
3. **id + 版本**：剧本 id、角色 id、system id、系统版本全部显式锁定；升级规则包只加版本号，老会话不受影响。
4. **不跨团继承**：玩家在别的团发生过的事、别的会话的线索与 NPC 关系，都不进入本场事实。
5. **私有区隔离**：`04-KP私有.md` 承载暗投数值、真相进度、未公开动机、判例，永不进入玩家可见叙述。

## 会话命名

`sessions/YYYY-MM-DD-<剧本id>-NN`，同一剧本开第二团时 NN 递增，避免覆盖。

## 规则系统的挂载

剧本在 `00-剧本概览.md` 声明 `规则系统: <id>` 与 `系统版本`；会话 manifest 再锁一次。换系统不改剧本正文，只改声明与 manifest。

系统包必须提供三件：`system.md`、`车卡规格.md`、`判定.md`（+ 可选专题文件如 `战斗与理智.md`）。

## 车卡审核

角色卡进入会话前必须过审，审核依据是 `systems/<系统id>/车卡规格.md`。

- 审核分两关：**数值**（能否复算、派生值是否自算、技能点与上限）与**叙事**（有没有预设剧本答案、预设权威人脉、万能型、能力越界）。任一处不合规即退回。
- 结果只有两种：通过 / 退回并列出条目号与具体数值。
- 未通过的角色不得进场；审核结果写进角色卡与 `00-本次设定.md`。
- 审核结论不接受玩家以扮演、剧情需要、其他团可以等理由推翻。
- 条文本身也会写错，所以每个系统包配一份 `审核用例.md`：必过与必退的样例卡，改条文后必须回归通过，不一致说明是条文错了。

## KP 的权限与义务

判定权只归 KP，玩家不能要求检定、不能宣布成功、不能改难度。抗嘴炮条款是硬性条款，见 `keeper/_framework.md` 第 5 节：

1. 难度一次定死，之后不因解释、举例、引经据典而改。
2. 扮演只能换奖励骰或免去无风险动作的掷骰，不能免掉有风险、有代价、有对抗的判定。
3. 规则争议一次裁定、记入判例、不再讨论。
4. 规则书没写的，不默认允许。
5. 玩家反复施压，重复同一句裁定。

## 骰源与明暗投

骰值要么由 KP 掷，要么由玩家用可验证工具掷并把输出贴进来；只报数字的自掷无效。

- 三档骰源：平台骰具 / 外部骰具或 `tools/roll.py`（带时间戳与种子，可复算）/ KP 自掷（日志标「未审计」）。
- 明投：默认。公布技能、难度、骰值、成功等级。
- 暗投：不公布骰值与等级，只给叙述。用于被动察觉、NPC 秘密行动、玩家无从知晓的对抗、公布即泄底的判定。
- **不设半明投**：只报等级仍可反推骰值区间，是假隔离。
- 暗投数值只进 `04-KP私有.md`，日志只标「（暗投）」。

## 记忆分层

跑团的上下文按四层管理，规则见 `docs/记忆管理.md`：

| 层 | 内容 | 装载 |
| --- | --- | --- |
| L0 硬事实 | 数值与物品、主线进度、关系边、承诺、时间锚点 | 全量，永不压缩 |
| L1 索引 | 支线、伏笔、未闭指针、未解之谜 | 全量，有上限，只留指向 |
| L2 摘要 | 每 3 场一块，只写决策 / 获得 / 失去 / 未闭环 | 最近 2 块全量，更早一行一块 |
| L3 原文 | 逐场日志 | 最近 2 场，超期用 `tools/archive_logs.py` 移入 `03-日志/归档/`，不删除 |

归档规则是「三问」：改变主线？改数值？留指针？三问全否即进当场日志的丢弃清单（留痕、可复活），不得在后文再提。

## 复核与申诉

场上不打断节奏，争议当场裁定；场后可复核，避免把模型或 KP 的首次误判制度化成永久判例。

1. 玩家按判例编号提复核，指出「哪条规则被误用」。
2. 由 KP 或第三方（店长、另一位 KP）裁定。
3. 成立 → 判例标「已修订」，写修订后的裁定与补偿方式，只影响后续，不重演过去。
4. 不成立 → 标「维持」，一句理由。

判例是「本场不重复讨论」的临时约定，不是终审。

## 玩家私有通道

多人桌的信息不对称由文件承接：`05-玩家私有/<角色id>.md` 记只有该角色知道的事、私下拿到的线索、与 KP 的一对一交流。只在对应角色单独行动时加载，公开叙述不得引用。

## 内容分级

manifest 必填 `内容分级`（L0–L3），KP 不得越过上限。有未成年参与者默认 L1，升 L2 需全体同意并记录。随时可喊停，喊停不需要理由、不记账。

## 注意力分层

| 层级 | 处理 | 落盘 |
| --- | --- | --- |
| 主线 | 每场至少推进一个节点，信息必须有保底路径 | 日志 + 状态跟踪 |
| 支线 | 玩家主动触碰才展开，单场不超过三分之一 | 状态跟踪（标支线） |
| 即兴 | 一句话闭环 | 不落盘、不设伏笔、不重复给戏 |

升级禁令：即兴事件要变剧情线，必须与已知主线线索直接咬合，并在 `04-KP私有.md` 登记理由；未登记的不得升级。

判据一句话：**这件事删掉，主线是否受损？不损，就是即兴。**

## 扩展方式

| 要加什么 | 怎么做 |
| --- | --- |
| 新剧本 | `scenarios/<id>/`，填 00–05，声明规则系统、系统版本、形态 |
| 新规则系统 | `systems/<id>/`，抄 `_template`，写满 system / 车卡规格 / 判定 / 成长，并附审核用例 |
| 新人设 | `keeper/personas/<名>.md`，只写语气与叙事偏好 |
| 新开一团 | `python tools/new_session.py --scenario <id> ...`，再跑 `tools/check_session.py` |
| 改动已跑过的团 | 只改 `sessions/<session_id>/` 内的副本，不回写母本；确有价值再手动合并并升版 |

## 成长与长团记忆

- 成长规则进系统包（`systems/<系统>/成长.md`）：COC 走技能成长检定与 SAN 恢复，D&D 走升级与恢复。成长只改会话副本。
- 长团记忆分四层：`状态跟踪.md` 是 L0 硬事实（数值、主线进度、关系边、承诺），`03-日志/前情提要.md` 上半是 L1 索引（支线、伏笔、指针），下半是 L2 摘要（每 3 场一块），`03-日志/日志-00N.md` 是 L3 原文（只留最近两场）。细节见 `docs/记忆管理.md`。

## 机械校验

Markdown 本身没有强制力，所以把能机械判断的部分交给脚本：

| 工具 | 作用 |
| --- | --- |
| `tools/new_session.py` | 按模板生成会话，回填 manifest，复制剧本与角色卡 |
| `tools/check_session.py` | 开局前预检：必填字段、占位符残留、清单路径、系统版本一致、剧本声明一致、角色过审、必备文件 |
| `tools/export_stats.py` | 汇总日志为 CSV：场次时长、检定数、明暗投、失败率、审核退回数 |

脚本挡得住的是「忘了同步版本、角色没过审就进场、清单写了不存在的文件」这类确定性错误；挡不住模型在运行时读清单外的文件——那一层需要运行环境的工具权限，纯 Markdown 项目做不到。

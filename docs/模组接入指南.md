# 模组接入指南

## 为什么不能「下载即跑」

六件骨架是对原模组的**有损压缩**：它丢掉原文台词、冗余背景、大量支线，只保留「真相 → 线索 → 场景 → 结局」这条因果骨架。压缩哪部分、保哪条保底路径，必须人来判断。任何工具都只能帮你抽文本，不能替你决定「这条线索删掉后主线会不会断」。

所以接入的准确说法是：**放进 `scenarios/` 之前，要先按骨架改写一遍**，改写成本约等于一次备团。

## 四种形态与骨架的对应

| 形态 | 原模组的样子 | 骨架怎么落 |
| --- | --- | --- |
| 线性 | 一幕接一幕 | 主线节点 = 场景序列；每幕的「出口」写成下一幕触发条件 |
| 调查 / 节点式 | 线索图、真相分层 | 主线节点 = 真相层级（表层 → 中层 → 真相）；03 里做线索-指向映射 |
| 沙盒 | 地点表 + 势力 + 定时器 | 主线节点 = 定时器事件（时间到就发生，不等玩家）；03 写成地点清单 |
| 混合 | 大部分商业模组 | 主线节点 = 3–5 个不可跳过的推进点，其余进支线 |

剧本概览的 `剧本形态` 字段必须与上面一致，因为 KP 的推进方式不同：线性靠场景切换，沙盒靠时间压力，调查靠线索咬合。

## 转换六步

1. **通读并划真相线**：谁做了什么、因果链、时间顺序 → `01-背景与真相.md`。这一步不许跳，后面全部依赖它。
2. **列 NPC**：每个出场者写动机、秘密、被质问时的反应 → `02-登场人物.md`。原模组里没有动机的龙套，一句语气设定即可。
3. **抽线索与地点**：每条线索必须有「指向」，没有指向的线索删掉；每个地点必须至少一条线索，且给一条**失败也能给**的保底 → `03-线索与调查点.md`。
4. **定关键场景**：3–6 幕必须出现的场面，写目的、氛围、可能的判定与分支 → `04-关键场景.md`。
5. **写结局条件**：圆满 / 残缺 / 惨胜 / 失控四档，各自的达成条件 → `05-结局分支.md`。
6. **回填概览**：形态、规则系统、推荐人数、**单人可跑（是 / 需改写 / 否）**、**来源与许可**、主线节点表（每个节点写「必须给出的信息」和「保底路径」）→ `00-剧本概览.md`。要单人跑就按 `docs/单人玩法.md` 的五条过一遍。
7. **写车卡约束**：概览的「车卡约束」一节只写**本模组对系统的额外限制**（身份范围、可用职业、必用技能、语言与时代、预生成卡、装备限制）。车卡规则本身留在 `systems/<系统>/车卡规格.md`，**不要复制进模组**。

## 为什么车卡模板按系统放，不按模组放

三层，各管一件事：

| 层 | 文件 | 管什么 | 谁改 |
| --- | --- | --- | --- |
| 系统层 | `systems/<系统>/车卡规格.md` | 属性怎么来、点数怎么分、派生值公式、审核退回清单 | 系统维护者，改一处全系统生效 |
| 模组层 | `scenarios/<id>/00-剧本概览.md` 的「车卡约束」 | 这个本允许什么人进、必须会什么 | 剧本作者 |
| 会话层 | `00-本次设定.md` 的本团约定 + 角色卡内的 house rule | 本桌临时放宽（单项上限、法器裁定等） | KP，开团时定 |

按模组复制一份车卡规格的代价是：N 个模组就有 N 份分叉，审核口径会漂，改一条规则要改 N 处，而且玩家换本时卡带不走。

## 本地模组（下载来的商业/免费模组）

商业模组与同人翻译**不进仓库**，放在这两个位置：

```
scenarios/local/<模组id>/          # 六件骨架 + 原始 PDF
sessions/local/<日期>-<模组id>-NN/  # 本地模组开的会话
```

- 两者都已在 `.gitignore` 里，`git status` 不会出现，也不会被推到公开仓库。
- 建会话时加 `--local`：
  ```bash
  python tools/new_session.py --scenario the-haunting --system coc7 \
      --characters lin-yan --rating L1 --local
  ```
- 概览里必须填 `来源`（作者 + 出处）与 `许可`（「版权归 X，仅供本机测试，不 redistribution」），否则预检会给提醒。
- 原始 PDF 留在 `scenarios/local/<模组id>/原始/`，方便日后核对转录是否失真。

## 跨系统移植

从 COC 模组改成 D&D 跑，或反过来，只改三处：

1. 概览的 `规则系统` 与 `系统版本`。
2. `03` 与 `04` 里的技能名换成目标系统技能；难度按下面换算。
3. 数值类障碍（血量、对抗值）按目标系统重估，不同系统之间没有精确换算。

| 原难度 | COC（d100） | D&D（d20） |
| --- | --- | --- |
| 简单 | 常规 | DC 10 |
| 普通 | 困难 | DC 15 |
| 困难 | 极难 | DC 20 |

## 接入检查表

开团前逐项确认，缺一项就不算接入完成：

- [ ] 每个主线节点都有「必须给出的信息」与「保底路径」
- [ ] 每条线索都有指向，没有孤立线索
- [ ] 每个调查点至少一条线索，其中一条是失败也能拿到的
- [ ] 每个 NPC 都有动机，且写明被质问时的反应
- [ ] 结局四档都有达成条件
- [ ] 概览声明了 `规则系统` 与 `系统版本`
- [ ] 概览声明了 `剧本形态`，且与骨架写法一致
- [ ] 内容分级已标注，并与目标玩家群体相符

## 版权

外部下载的模组（含同人翻译、未授权搬运）**不进这个仓库**。仓库只放自己写的剧本，或明确授权可再分发的。详见 `docs/内容与版权.md`。
